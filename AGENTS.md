# AGENTS.md — правила для всех агентов (читать первым)

## Цель
Прототип: по набору изображений (кадры с камер служебных автомобилей МГТС) находит объекты
инфраструктуры (колодцы, опоры, шкафы), оценивает состояние, выдаёт перечень объектов,
требующих проверки/ремонта, с координатами. Формат результата: CSV + GeoJSON + HTML-карта + веб-демо.

## Порядок чтения
1. `README.md` → 2. `docs/ARCHITECTURE.md` → 3. `docs/DATA_CONTRACTS.md` → 4. **`docs/API_SPEC.md`** (низкоуровневая
спецификация: сигнатуры, алгоритмы по шагам, крайние случаи) → 5. `tasks/TDD.md` → 6. **свой** файл `tasks/agent_N_*.md`.

## Работа по TDD (обязательно)
Для каждой функции: **красный тест → коммит → минимальный код → зелёный тест → коммит → рефакторинг → ревью**.
Подробности и команды: `tasks/TDD.md` (`make red` — заглушки считаются упавшими, `make green` — приёмка без пропусков).
Нет падающего теста — нет права писать код. Тест не подгоняется под код.
Ревью перед мержем: скилл из `skills/review/`.

## Золотые правила
1. **Контракты заморожены.** `src/mgts/schemas.py` и сигнатуры функций, помеченные `# CONTRACT`, не менять.
   Нужно изменение — написать в `tasks/CONTRACT_REQUESTS.md` (одна строка) и продолжить с обходным путём.
2. **Только свои директории.** Каждый агент владеет своими файлами (таблица ниже). Чужие файлы не править.
3. **Конфиг.** Параметры — в `configs/default.yaml`, но правишь только свою секцию. Никаких «магических» чисел в коде.
4. **Заглушки → реализации.** Функции с `raise NotImplementedError` заменяются рабочим кодом. Тесты в `tests/`
   автоматически пропускаются, пока функция — заглушка, и становятся обязательными, когда она реализована.
5. **Всегда работающий прототип.** Сначала простой вариант end-to-end, потом улучшения.
   Запрещено «почти готово, но не запускается». Перед коммитом: `pytest` зелёный.
6. **Без блокировок.** Нет датасета/весов/GPU — используй fallback из своего задания, не жди других агентов.
7. **Коммиты** маленькие и частые, ветка `agentN-<тема>`. Агент 4 мержит в `main` и следит за `make e2e`.
8. **Объяснимость.** Каждый найденный дефект возвращается с `DefectFinding.evidence` (человекочитаемое
   основание, например «наклон 9.3° > порога 8°»). Неуверенное → `needs_review=True`, а не молчаливая ошибка.
9. **Пропуск дефекта дороже ложной тревоги.** При подборе порогов приоритет — recall по дефектным объектам.
10. **Язык:** код и идентификаторы — английский, комментарии/докстринги/документы — русский.

## Definition of Done (общий)
- `pytest` зелёный, `make e2e` отрабатывает на демо-данных и на реальном датасете.
- Каждая публичная функция имеет докстринг и тип аргументов.
- Свой раздел в `docs/` обновлён: что сделано, какие пороги, какие метрики получены.
