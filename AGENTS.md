# Правила работы с MGTS Infra Vision

## Текущее состояние

Прототип реализован: анализ и подготовка датасета, детекция, оценка состояния, GPS, дедупликация, экспорт, CLI и Streamlit. Реального датасета пока нет, поэтому точность детектора и эвристик на реальных кадрах не подтверждена.

`tasks/agent_*.md` описывают следующие работы на данных, а не задания на повторную реализацию модулей. Перед изменением сначала проверь текущий код и тесты. `dummy` читает готовую YOLO-разметку и предназначен только для интеграционного демо.

## Установка и проверки

- `make install-dev` — базовые зависимости, CLI, демо и тесты.
- `make install` — дополнительные зависимости для обучения YOLO и Streamlit.
- `make green` — полный тестовый прогон в строгом режиме.
- `make demo-data && make e2e` — проверка сквозного демо без модели.
- `uv.lock` — закреплённые версии; после изменения зависимостей обновить его через `uv lock`.

## Правила изменений

- Бизнес-логика находится в `src/mgts/`, её поведение проверяется тестами в `tests/`.
- Новые функции снабжать type hints и тестами для значимого поведения и ошибок.
- Не скрывать ошибки кадра: пайплайн продолжает запуск, пишет детали в лог и `summary.json`.
- Не подменять отсутствующие GPS-координаты нулями и не представлять демо-результаты как метрики качества.
- Веса, данные и результаты запусков не добавлять в git.
- При передаче исходников архивом отдельно указывать commit SHA: архив GitHub не содержит `.git`.
