# MGTS Infra Vision

Программа анализирует фотографии улиц с автомобиля: находит инфраструктурные объекты, оценивает их состояние и сохраняет список для проверки.

## Самые нужные команды

Запускайте из корня проекта. `make install-dev` создаёт `.venv`; активируйте её перед остальными командами:

```bash
make install-dev # CLI, демо и тесты без тяжёлых ML/UI-зависимостей
source .venv/bin/activate
make demo-data   # создать тестовые кадры и готовую разметку
make e2e         # проверить весь путь обработки на демо-данных
make install     # полный набор, нужен для обучения YOLO и веб-интерфейса
make app         # открыть веб-интерфейс после make install
make test        # запустить тесты
mgts --help      # посмотреть команды CLI
```

## Первый запуск

Установите [uv](https://docs.astral.sh/uv/getting-started/installation/) и выполните:

```bash
make install-dev
source .venv/bin/activate
```

`make install-dev` ставит базовые зависимости и pytest — этого достаточно для демо, CLI и тестов. `make install` ставит также PyTorch/Ultralytics и Streamlit. Версии всех зависимостей закреплены в `uv.lock`; при изменении зависимостей обновляйте его командой `uv lock`.

## Демо за пару минут

```bash
make demo-data
make e2e
```

Результаты появятся в `outputs/e2e/`: таблица `objects.csv`, файл `objects.geojson`, карта `map.html`, обработанные кадры и сводка `summary.json`.

Демо использует `dummy`: он читает готовые рамки из файлов разметки рядом с изображениями. Это проверка программы, а не автоматическое распознавание.

Чтобы открыть демо в браузере:

```bash
make app
```

В боковом меню выберите папку `data/demo/images` и запустите анализ. Если обученной модели ещё нет, интерфейс предупредит о демо-режиме.

Для реальной обработки сначала обучите детектор, затем загрузите фотографии или укажите папку и выберите YOLO. GPS-трек можно загрузить отдельно.

## Запуск на своих фотографиях

### 1. Положите данные в `data/raw/`

Обычная структура для YOLO:

```text
data/raw/
├── images/       # фотографии
├── labels/       # одноимённые .txt с рамками YOLO
└── frames.csv    # GPS-трек, если есть
```

Также поддерживаются COCO JSON, Pascal VOC XML и CSV-разметка. Перед подготовкой проверьте, что имена и порядок классов в `configs/classes.yaml` совпадают с разметкой.
Для CSV-разметки нужны колонки `filename, class, xmin, ymin, xmax, ymax`; подробности — в [`docs/DATA_CONTRACTS.md`](docs/DATA_CONTRACTS.md).

### 2. Посмотрите, что в датасете

```bash
mgts analyze --dataset data/raw
```

### 3. Приведите данные к формату обучения

```bash
mgts prepare --src data/raw --fmt auto
```

Допустимые значения `--fmt`: `auto`, `yolo`, `coco`, `voc`, `csv`. Команда создаёт `data/processed/` и вырезки объектов в `data/crops/`.

### 4. Обучите детектор

```bash
mgts train-det
```

Команда ожидает размеченный датасет в `data/processed/` и базовые веса YOLO, заданные в `configs/default.yaml`. Результат сохраняется как `models/detector.pt`. При `device: auto` программа использует GPU, если он доступен, иначе обучает на CPU.

Для базовой модели из текущего конфига (`yolov8s.pt`) скачайте веса в `models/`:

```bash
curl -L https://github.com/ultralytics/assets/releases/download/v8.3.0/yolov8s.pt -o models/yolov8s.pt
```

Это только стартовые веса COCO, а не модель, обученная на объектах инфраструктуры. Для CPU можно скачать меньшую `yolov8n.pt`; путь уже учитывается при автоматическом выборе CPU-модели.

Если хотите явно выбрать CPU, создайте `configs/local.yaml`:

```yaml
detection:
  device: cpu
```

Затем добавьте `--config configs/local.yaml` перед подкомандой, например: `mgts --config configs/local.yaml train-det`.

### 5. Запустите обработку

С обученным детектором и CSV/GPX-треком:

```bash
mgts run \
  --input data/raw/images \
  --track data/raw/frames.csv \
  --output outputs/real-run \
  --backend yolo
```

Если GPS-трека нет, уберите строку `--track ...`. Координаты попробуют прочитать из EXIF; если их нет, местоположение останется неизвестным.

Чтобы проверить готовую YOLO-разметку без инференса модели, запустите `dummy`:

```bash
mgts run \
  --input data/processed/images \
  --output outputs/labels-check \
  --backend dummy
```

`dummy` требует соответствующие файлы в `data/processed/labels/` и не подходит для фотографий без разметки.

## Классификатор состояния и метрики

Обучение классификатора состояния необязательно. Оно имеет смысл, если в вырезках есть метки `ok` и дефектов:

```bash
mgts train-clf
```

Без таких меток программа продолжает работу с геометрической оценкой состояния.
Файл классификатора `*.pkl` загружается через `pickle`: используйте только веса, которым доверяете. Загрузка чужого pickle-файла может выполнить произвольный код.

Метрики детектора на отложенной выборке:

```bash
mgts eval-det --split val
```

Обучение детектора также запускает оценку автоматически. Результаты сохраняются в `models/detector_metrics.json`.

## GPS и результаты

Трек можно передать в формате CSV или GPX через `--track`. Для CSV подходят колонки `frame_id`, `lat`, `lon`, `heading_deg`, `timestamp`.

- Если кадр сопоставился с треком — используются его координаты.
- Если трек есть, но точного совпадения нет — используется приблизительная точка трека и помечается как приблизительная.
- Если GPS нигде нет — координаты неизвестны. Объект всё равно остаётся в списке.

Каждый запуск создаёт в папке из `--output`:

- `objects.csv` — список объектов;
- `objects.geojson` — объекты для ГИС;
- `map.html` — карта и список объектов без координат;
- `annotated/` и `crops/` — изображения для проверки;
- `summary.json` — число кадров, объектов, ошибки по каждому кадру (`frame_errors`) и время этапов.

Если команда `mgts` не найдена, используйте эквивалент:

```bash
python -m mgts.cli --help
python -m mgts.cli run --input data/raw/images --output outputs/run1 --backend yolo
```

## Логи и тесты

Обычный уровень логов показывает основные этапы. Чтобы увидеть подробности по кадрам:

```bash
MGTS_LOG_LEVEL=DEBUG mgts run --input data/raw/images --output outputs/run1
```

Проверки проекта:

```bash
make test       # все тесты
make green      # алиас полного тестового прогона
```

## Что важно знать

- `models/yolov8n.pt` и `models/yolov8s.pt` — базовые веса; они не обучены распознавать объекты этого проекта. Для реального распознавания обучите детектор на размеченных данных.
- Команда скачивания базовых весов приведена в разделе «Обучите детектор»; сами веса в репозиторий не входят.
- Результаты на демо-данных не являются метриками качества модели.
- Проекция GPS на объект использует начальные параметры камеры из `configs/default.yaml`; для реальной эксплуатации их нужно откалибровать.
- Текущий статус проекта и уже проверенные сценарии сохранены в [`docs/PROJECT_CONTEXT.md`](docs/PROJECT_CONTEXT.md). Термины проекта — в [`CONTEXT.md`](CONTEXT.md).
