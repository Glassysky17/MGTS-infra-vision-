# Архитектура

## Идея
Двухэтапный гибридный подход:
1. **Детектор** (YOLO, дообученный) находит объекты инфраструктуры на кадре, мелкие — через тайловую нарезку.
2. **Модуль состояния** по вырезке каждого объекта считает признаки дефектов: **классические алгоритмы компьютерной
   графики** (PCA/Хаф для наклона, контуры и эллипсы для люков, black-hat для трещин, HSV для коррозии) +
   **классификатор** на предобученной CNN. Геометрия даёт объяснимость и работает при малом числе размеченных дефектов.
3. **Гео-слой** переводит пиксель основания объекта в координаты по модели камеры-обскуры и плоскости земли.
4. **Дедупликация** схлопывает повторные наблюдения одного объекта в разных кадрах.
5. **Экспорт**: перечень с приоритетами (CSV), GeoJSON, HTML-карта, веб-демо.

## Схема потока данных

```
 images/ (+ GPS: EXIF | CSV | GPX)
      │
      ▼
 [geo.gps.build_frame_meta] ──► FrameMeta(lat, lon, heading)
      │
      ▼
 [preprocessing.quality.blur_score] ── размытые кадры отбрасываем
      │
      ▼
 [preprocessing.enhance]  (CLAHE/gamma) ── только для детектора
      │
      ▼
 [detection.build_detector → .detect]  (YOLO + тайлинг) ──► list[Detection]
      │
      ▼   (для каждой детекции, по ОРИГИНАЛЬНОМУ кадру)
 [condition.scoring.assess]  геометрия + классификатор ──► ConditionAssessment
 [geo.project.estimate_object_position] ──► lat/lon объекта
      │
      ▼
 list[Observation]
      │
      ▼
 [geo.dedup.merge_observations] + [condition.scoring.priority_for] ──► list[ObjectRecord]
      │
      ▼
 [export] objects.csv · objects.geojson · map.html · annotated/ · crops/ · summary.json
      │
      ▼
 [app/streamlit_app.py] / [mgts run]
```

## Модули и ответственные

| Модуль | Файлы | Агент |
|---|---|---|
| Данные | `data/analyze, convert, split, crops, augment, synth_defects`, `scripts/make_demo_data.py` | 1 |
| Предобработка | `preprocessing/quality, enhance` | 2 |
| Детекция | `detection/infer, tiling, train, evaluate` | 2 |
| Состояние | `condition/geometry, classifier, scoring` | 3 |
| Гео | `geo/gps, project, dedup` | 4 |
| Сборка | `pipeline, export, cli`, `app/streamlit_app.py` | 4 |

## Границы между агентами (интерфейсы)

- A1 → A2: `data/processed/` (YOLO + `data.yaml` + `train.txt/val.txt`).
- A1 → A3: `data/crops/` (вырезки + `index.csv`) и синтетические дефекты.
- A2 → A4: `build_detector(cfg).detect(img, frame_id, image_path) -> list[Detection]`; `blur_score`, `enhance`.
- A3 → A4: `assess(frame, detection, cfg, classifier, classes) -> ConditionAssessment`, `priority_for(...)`.
- A4 → все: `run_pipeline`, `mgts run`.

Главное: **контракты (schemas.py + сигнатуры) заморожены**, поэтому все четверо работают одновременно и независимо;
`DummyDetector` и демо-данные позволяют отлаживать интеграцию до появления модели и реального датасета.

## Принятые решения и почему

| Решение | Причина |
|---|---|
| YOLO + дообучение | быстро, хорошо для мелких объектов с тайлингом, есть предобученные веса |
| Собственный тайлинг вместо зависимости на SAHI | меньше зависимостей, полный контроль слияния, демонстрирует понимание алгоритма |
| Геометрия + классификатор | мало данных с дефектами; геометрия объяснима, классификатор ловит то, что не описать правилами |
| Оценка состояния по оригиналу, детекция по улучшенному кадру | CLAHE/гамма меняют цвет и текстуру -> ломают признаки ржавчины и трещин |
| `needs_review` вместо жёсткого вердикта | ложная уверенность хуже честного «проверьте вручную» |
| Приоритет = критичность класса × степень неисправности | эксплуатационщику нужен порядок объезда, а не только «плохо/хорошо» |
| Позиция объекта через проекцию на землю | позиция автомобиля даёт ошибку в 5–30 м, проекция — единицы метров |

## Обход рисков

| Риск | Что делаем |
|---|---|
| Нет данных с дефектами | синтез дефектов (трещины, ржавчина, наклон), геометрические правила без обучения |
| Мелкие объекты | тайлинг + повышенное разрешение |
| Размытие/свет/дождь | аугментации под условия съёмки, CLAHE, отбор резких кадров |
| Нет GPS в данных | трек CSV/GPX, интерполяция, иначе синтетические координаты с явной пометкой |
| Один объект в десятках кадров | дедупликация по гео + внешнему виду |
| Мало времени | `DummyDetector`, демо-данные, fallback без GPU в каждом задании |
