# Отчёт по датасету

**Выбранный сценарий для реальных данных: C — размеченного набора пока нет.** В `data/raw/` нет изображений и разметки; там оставлен только `.gitkeep`. Поэтому реальные распределения классов, размеры рамок, долю мелких объектов, качество кадров и наличие GPS посчитать нельзя.

Для разработки доступен детерминированный синтетический набор: `python scripts/make_demo_data.py --out data/demo --n 16 --seed 0`. В нём есть классы `cable_manhole` и `utility_pole`, повторные наблюдения физических объектов в трёх соседних кадрах, прямолинейный псевдо-GPS-трек с шагом 4 м и примеры трещины крышки/наклонённой опоры. Синтетические дефекты помечаются в `gt_defects.csv`; они не являются реальными данными и не заменяют ручную проверку.

## Выводы для дня 0

- До получения реальной выборки использовать демо-данные только для проверки пайплайна и форматов.
- Когда появится набор, запустить `mgts analyze --dataset data/raw`, проверить таблицы классов и размеров bbox, битые файлы, дубликаты и наличие GPS.
- Если будут только метки объектов, это сценарий B: состояние оценивать геометрией и синтетическими дефектами, явно отделяя эвристики от реальной разметки.
- Если найдутся дефектные метки или атрибуты, переключить отчёт на сценарий A и использовать их для классификатора; если разметки не будет — начать с CVAT/Label Studio (сценарий C).
- Класс с долей менее 5% отметить для балансировки. При разбиении кадров не допускать попадания серии/маршрута одновременно в train и val.

Запуск `analyze_dataset` создаёт Markdown-сводку и `dataset_samples.jpg` рядом с указанным файлом отчёта. Для фактических метрик и примеров повторить анализ после размещения данных в `data/raw/`.
