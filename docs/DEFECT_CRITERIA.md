# Критерии неудовлетворительного состояния

> Заполняет и уточняет Агент 3 в «день 0» по реальным кадрам. Пороги дублируются в `configs/default.yaml → condition`.
> Принцип: если признак нельзя уверенно увидеть на кадре с камеры автомобиля — не выдаём его как факт, ставим `needs_review`.

| Код | Объект | Как определяем | Порог по умолчанию | Статус (заполнить) |
|---|---|---|---|---|
| `pole_tilt` | опора | PCA по маске + Хаф, минус крен камеры | предупреждение 4°, дефект 8° | реализовано (геометрия) |
| `pole_crack` | опора | black-hat + скелетизация, классификатор | crack_score ≥ 0.55 | реализовано (геометрия + классификатор) |
| `corrosion` | опора, шкаф | доля «ржавых» HSV-пикселей в маске | предупреждение 10 %, дефект 25 % | реализовано (геометрия + классификатор) |
| `cover_broken` | колодец | трещины на крышке + классификатор | crack_score ≥ 0.55 | реализовано (геометрия + классификатор) |
| `cover_displaced` | колодец | округлость контура и тёмная щель вдоль контура | circularity < 0.85 или щель ≥ 0.50 | реализовано (геометрия) |
| `cover_missing` | колодец | классификатор («открытый колодец») | вероятность ≥ 0.5 или порог из condition_metrics.json | только классификатор |
| `subsidence_around` | колодец | текстура и края в кольце вокруг объекта | предупреждение 0.30, дефект 0.60 | реализовано (геометрия) |
| `cable_sag` | опора | классификатор | вероятность ≥ 0.5 или порог из condition_metrics.json | только классификатор |
| `cabinet_open` / `cabinet_damaged` | шкаф | классификатор | вероятность ≥ 0.5 или порог из condition_metrics.json | только классификатор |
| `generic_damage` | любой | бинарный классификатор «ok / defect» | вероятность ≥ 0.5 или порог из condition_metrics.json | только классификатор |

Классификатор использует CPU fallback `features_lr` (HSV-гистограмма, плотность краёв и геометрические признаки). Без обученных весов или размеченных вырезок он выключен: `predict()` возвращает пустой результат, оценка продолжается по геометрии.

## Агрегация
`score = 1 − Π(1 − wᵢ·sᵢ)` по найденным признакам (noisy-OR), `wᵢ` — вес из `classes.yaml`.
`severity`: `defect` при score ≥ 0.6, `warning` при ≥ 0.35, иначе `ok`; рядом с порогом (±0.1) → `uncertain` + `needs_review`.

## Когда ставим «требует ручной проверки»
- слабая детекция (score детектора < 0.3);
- вырезка слишком мала (< 24 px);
- геометрия и классификатор противоречат друг другу;
- итоговый score в пограничной зоне порога;
- кадр размыт/переэкспонирован в зоне объекта.

## Приоритет
`p = критичность_класса × score (+0.15 при cover_missing / cable_sag)`;
`critical ≥ 0.75`, `high ≥ 0.5`, `medium ≥ 0.25 или needs_review`, иначе `low`.

## Что мы осознанно НЕ делаем
Не оцениваем внутреннее состояние колодца и скрытую коррозию — только то, что видно с дороги.
Это нужно прямо сказать на защите.

## Ограничения
- При отсутствии весов классификатора недоступны дефекты без геометрического признака: открытая крышка, провисший кабель и повреждение/открытие шкафа.
- Геометрические правила чувствительны к сегментации, освещению и фактуре дорожного покрытия; пограничные результаты и слабая геометрическая уверенность требуют ручной проверки.
- Просадку и трещины можно оценивать только в видимой области кадра; окклюзии, мелкие дефекты и повреждения с обратной стороны объекта не определяются.
- Значения порогов стартовые и не откалиброваны на реальных кадрах; после появления размеченной выборки следует сверить ложные срабатывания и полноту.
