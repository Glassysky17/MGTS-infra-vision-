# Следующий этап: проверка на реальных данных

## Статус

Код прототипа реализован и покрыт тестами. Входных реальных данных пока нет. Файлы `agent_1_data.md`–`agent_4_integration.md` теперь содержат планы проверки, обучения и калибровки; они не требуют повторно создавать уже существующие модули.

Демо с `dummy` проверяет только интеграцию. Его цифры нельзя выдавать за точность модели или качество эвристик на реальных кадрах.

## До получения датасета

```bash
make install-dev
make green
make demo-data
make e2e
```

Для Streamlit и обучения моделей установите полный набор: `make install`.

## Когда датасет появится

1. Сохранить исходные данные в `data/raw/`, не изменяя оригиналы; изучить формат, классы, метки состояния и GPS.
2. Проверить классы в `configs/classes.yaml`, затем запустить `mgts analyze --dataset data/raw` и `mgts prepare --src data/raw --fmt auto`.
3. Зафиксировать разбиение и метрики датасета в `docs/DATASET_REPORT.md`; проверить отсутствие утечки между train и val.
4. Скачать базовые веса по команде из README, обучить детектор (`mgts train-det`) и оценить его (`mgts eval-det --split val`).
5. На реальных кадрах откалибровать `detection.conf`, размытие, геометрию камеры и пороги состояния. Классификатор обучать только при наличии размеченных кропов.
6. Прогнать `mgts run` на отложенных данных, вручную проверить ошибки и записать ограничения и метрики в отчёты.

Не запускать обучение и не менять пороги по синтетическому демо.
