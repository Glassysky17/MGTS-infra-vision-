# Как запускать агентов

## Идея
4 агента работают **параллельно** по замороженным контрактам, каждый в своих папках.
Ориентир: **2 часа** на всё после получения датасета.

## Перед запуском (человек, 15 минут)
1. Клонировать репозиторий, `make install`, `pytest` — контракты зелёные, остальное «skipped».
2. Выполнить `tasks/00_day0_checklist.md` шаги 1–3: положить датасет в `data/raw/`, посмотреть вручную 20–30 кадров,
   поправить `configs/classes.yaml` (классы, дефекты) и решить, какой сценарий данных у вас (A/B/C из чек-листа).
3. Закоммитить в `main`, создать ветки: `agent1-data`, `agent2-detection`, `agent3-condition`, `agent4-integration`.

## Промпт для каждого агента (копировать целиком, подставить N и имя файла)

```
Ты — Агент N в команде из 4 агентов, которые параллельно дописывают проект из этого репозитория
(система мониторинга инфраструктуры МГТС по снимкам: детекция объектов + оценка состояния + геопривязка).
Работаешь в ветке agentN-<тема>.

1. Прочитай по порядку: AGENTS.md, docs/ARCHITECTURE.md, docs/DATA_CONTRACTS.md, docs/API_SPEC.md, tasks/TDD.md,
   tasks/<ФАЙЛ_АГЕНТА>.md. Сигнатуры и поведение функций бери из docs/API_SPEC.md и докстрингов — не придумывай своих.
2. Выполняй задачи из своего файла строго по порядку; заглушки (raise NotImplementedError) заменяй рабочим кодом.
3. Работай по TDD: сначала красный тест (`MGTS_STRICT=1 pytest <тест>` падает) и коммит `test: red …`,
   затем минимальный код и коммит `feat: …`, затем рефакторинг. Код без падающего теста писать нельзя.
4. Меняй только свои файлы и секции конфига (таблица владельцев в AGENTS.md). Контракты не менять.
5. После каждой функции: `pytest tests/<твой_файл>`, затем ревью по `skills/review/SKILL.md`; коммить. Не останавливайся и
   не спрашивай разрешения между задачами — на неоднозначность выбирай разумный вариант, записывай решение в docs/ и иди дальше.
6. Если не хватает данных/GPU/весов — используй fallback из своего файла, не жди других агентов.
7. Время: около 100 минут. Сначала простейшая рабочая версия всех задач, потом улучшения.
8. В конце: обнови свой раздел docs/, убедись что pytest зелёный, кратко напиши, что сделано, какие пороги/метрики получены,
   что не успел.
```

| Агент | Файл | Ветка |
|---|---|---|
| 1 | `tasks/agent_1_data.md` | `agent1-data` |
| 2 | `tasks/agent_2_detection.md` | `agent2-detection` |
| 3 | `tasks/agent_3_condition.md` | `agent3-condition` |
| 4 | `tasks/agent_4_integration.md` | `agent4-integration` |

## Таймлайн (минуты от старта агентов)

| Время | A1 Данные | A2 Детекция | A3 Состояние | A4 Интеграция |
|---|---|---|---|---|
| 0–15 | demo-данные, analyze | `DummyDetector`, quality/enhance | geometry на синтетике | gps, project |
| 15–40 | convert, split, crops | tiling, YoloDetector | geometry + scoring | dedup, export |
| 40–70 | augment, synth_defects | train_detector (**запуск обучения**) | classifier на crops | pipeline, cli |
| 70–100 | расширенная синтетика под слабые классы | evaluate, подбор conf | train_classifier, пороги | Streamlit, e2e |
| 100–120 | **совместная интеграция**: `make e2e` на реальном датасете, подбор порогов, README, демо | | | |

Критические точки синхронизации:
- **T+15**: A1 сдал `make_demo_data` и A2 сдал `DummyDetector` → A4 может запускать `make e2e` с заглушками.
- **T+40**: A1 сдал `data/processed` и `data/crops` → A2 запускает обучение, A3 начинает классификатор.
- **T+100**: все ветки смержены в `main` (мержит A4, порядок: 1 → 2 → 3 → 4).

## Если агент — слабая модель
Низкоуровневые алгоритмы по шагам лежат в `docs/API_SPEC.md`. Давайте агенту **одну функцию за раз**:
«реализуй `tiling.tile_slices` по API_SPEC §2 по TDD». Не давайте весь файл задания целиком, пока не готовы первые функции.
Проверка результата — `MGTS_STRICT=1 pytest tests/<файл>`.

## Правила мержа (для A4 / человека)
1. `git merge agent1-data`, `pytest` → 2. `agent2-detection` → 3. `agent3-condition` → 4. `agent4-integration`.
2. После каждого мержа: `pytest && make e2e`. Конфликты в `configs/default.yaml` решать по принципу «каждая секция принадлежит владельцу».
3. Если e2e падает — чинит тот, чья функция в трейсбеке; контракты не ломать.
