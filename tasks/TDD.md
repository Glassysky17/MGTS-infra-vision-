# TDD: красный тест → зелёный код → рефакторинг

Обязательно для всех агентов. Цикл на КАЖДУЮ функцию:

1. **RED.** Открой тест в `tests/` (уже есть) и допиши недостающие: крайние случаи, ошибки, свойства из `docs/API_SPEC.md`.
   Запусти строго: `MGTS_STRICT=1 pytest tests/<файл>::<тест> -x` — тест ОБЯЗАН упасть (заглушка тоже считается красным).
   Если тест зелёный до написания кода — тест бесполезен, ужесточи его.
2. **Commit red:** `git commit -m "test(<модуль>): red — <что проверяет>"`.
3. **GREEN.** Напиши минимальный код, чтобы тест позеленел. Не добавляй поведение, которого нет в тестах.
   Запусти тот же тест, затем весь файл: `MGTS_STRICT=1 pytest tests/<файл>`.
4. **Commit green:** `git commit -m "feat(<модуль>): <функция>"`.
5. **REFACTOR.** Почисти код, тесты остаются зелёными. Докстринг и типы на месте.
6. **Review.** Прогони скилл ревью (`skills/review/`), исправь замечания, `git commit -m "refactor/fix: ..."`.

## Правила
- Не пиши код без падающего теста. Не правь тест, чтобы он прошёл (кроме явной ошибки в самом тесте — тогда отдельный коммит `test: fix`).
- Один тест — одно поведение; имя `test_<функция>_<ситуация>`; данные генерируй в тесте (`tests/helpers.py`), внешних файлов нет.
- Для каждой функции минимум: нормальный случай, пустой/вырожденный вход, граница порога.
- Тесты быстрые (< 1 с каждый), детерминированные (`np.random.default_rng(seed)`).
- Перед мержем ветки: `MGTS_STRICT=1 pytest` зелёный по **твоим** файлам; в обычном режиме `pytest` не имеет падений.

## Режимы запуска
| Команда | Поведение |
|---|---|
| `pytest` | заглушки (`NotImplementedError`) = skipped, реализованное = обязательно зелёное |
| `MGTS_STRICT=1 pytest` | заглушки = FAILED (красный) — режим TDD и приёмки |
| `make red` / `make green` | то же самое короткими командами |

## Шаблон теста (копируй)
```python
def test_blur_score_black_image_is_zero():
    img = np.zeros((100, 100, 3), np.uint8)          # Arrange
    assert blur_score(img) == 0.0                     # Act + Assert
```
