# Агент 3 — Оценка состояния

**Миссия:** по вырезке объекта определить признаки неудовлетворительного состояния и объяснить решение.
Здесь главный козырь команды — классические алгоритмы компьютерной графики (контуры, PCA, Хаф, морфология,
цветовые пространства), дополненные классификатором.

**Ветка:** `agent3-condition`. **Владеешь:** `src/mgts/condition/`, `docs/DEFECT_CRITERIA.md`, секция `condition`.
**Тесты:** `tests/test_condition.py`; вспомогательные генераторы — `tests/helpers.py` (рисуют опоры и люки).

> Работай по TDD (`tasks/TDD.md`). Алгоритмы по шагам — `docs/API_SPEC.md` §3.

## Порядок задач

### §1. `condition/geometry.py` — геометрия (без обучения; делай ПЕРВЫМ)
Работай сразу на синтетике из `tests/helpers.py`, реальные кадры подключишь позже.
1. `segment_foreground` — маска объекта: GrabCut по центральному прямоугольнику или адаптивный порог + морфология +
   крупнейшая компонента; вырожденные маски → пустая маска.
2. `estimate_pole_tilt` — PCA по пикселям маски (главная ось → угол к вертикали) + проверка через `HoughLinesP`;
   при расхождении >3° снижать `confidence`; для не вытянутых масок `confidence≈0`. Знак: наклон вправо → «+».
3. `vertical_reference_angle` — крен камеры по вертикальным линиям всего кадра (медиана углов Хафа в ±15°).
   Итоговый наклон опоры = измеренный − крен камеры.
4. `analyze_hatch` — контур люка → `circularity`, `cv2.fitEllipse` и невязка, доля тёмной щели вдоль контура.
5. `crack_score` — black-hat + порог + скелетизация (`skimage.morphology.skeletonize` или собственная
   итеративная утончающая операция на cv2) → длина связных ветвящихся структур / периметр.
6. `corrosion_ratio` — HSV-маска ржавого цвета, фильтр мелких пятен.
7. `surface_subsidence_score` — кольцо вокруг bbox vs фоновая полоса: плотность краёв и дисперсия яркости.
Тесты: `test_tilt_*`, `test_segment_*`, `test_round_hatch_*`.
**Принцип:** каждая функция возвращает число и не падает на мусоре (пустой/маленький кроп → нейтральное значение).

### §3. `condition/scoring.py` — сборка оценки (делай до классификатора, чтобы A4 был разблокирован)
`assess` — точка входа для pipeline. Реализуй по докстрингу: кроп с полями → геометрические проверки по классу →
`DefectFinding` с `evidence` → noisy-OR агрегация → severity → `needs_review`. Затем `priority_for`.
Критично:
- `evidence` на человеческом языке и с числами: «наклон 9.3° > порога 8.0°»;
- `assess` **никогда не бросает исключения** (логируй и пропускай признак);
- без классификатора (`classifier=None` или `is_ready=False`) работает на одной геометрии.
Тесты: `test_assess_*`, `test_priority_*`. **К T+40 функция должна работать на геометрии** — тогда A4 интегрирует.

### §2. `condition/classifier.py` — классификатор по кропам
Начни с `features_lr` (быстрый fallback, работает на CPU за минуты): признаки HSV-гистограмм, краёв, `crack_score`,
`corrosion_ratio`, `circularity` → `LogisticRegression`/`GradientBoosting`. Потом, если есть GPU/время,
`efficientnet_b0`/`resnet18` (torchvision, веса ImageNet; сначала голова 2–3 эпохи, затем всё с lr/10).
- Источники: `data/crops/` (A1) + синтетика (`synthetic=1`). Валидацию считай на реальных, если они есть.
- Мультиметочная постановка по кодам дефектов из `classes.yaml`; пороги по каждому коду подбирай по F2 (recall важнее).
- Метрики в `models/condition_metrics.json`.
- `predict` возвращает `{}`, если весов нет.
Время обучения ≤ 10 минут на CPU.

### §4. Калибровка на реальных кадрах
Когда придёт датасет: прогнать `assess` по реальным кропам, посмотреть 30 случаев вручную, подправить пороги в
`configs/default.yaml → condition` и таблицу в `docs/DEFECT_CRITERIA.md`. Особенно: ложные срабатывания `crack_score`
на рёбрах люка и швах асфальта; крен камеры при оценке наклона.

### §5. Отчёт
В `docs/DEFECT_CRITERIA.md` заполни колонку «Статус» (реализовано / только классификатор / не поддерживается) и
добавь раздел «Ограничения» (какие дефекты по кадру с дороги не видны).

## Критерии приёмки
- [ ] `pytest tests/test_condition.py` зелёный (без заглушек).
- [ ] На синтетике: наклон измеряется с ошибкой ≤ 1.5°; прямая опора не помечается `defect`.
- [ ] `assess` отдаёт `evidence` для каждого `finding`, не падает на пустых/мелких кропах.
- [ ] `needs_review` срабатывает в 5 условиях из докстринга.
- [ ] Классификатор обучен или честно отключён (`is_ready=False`) — система работает в обоих режимах.

## Fallback
- Нет дефектных меток и мало данных: опирайся на геометрию + синтетику A1, классификатор делай бинарным
  `ok / defect` (код `generic_damage`).
- Нет `scikit-image`: скелетизация через собственную итерационную эрозию (Zhang-Suen на numpy) или оценка длины через
  `cv2.ximgproc.thinning`, если доступен contrib; иначе используй площадь black-hat маски как прокси.
- GrabCut медленный/нестабилен: адаптивный порог + морфология.
- Не успеваешь по классу: приоритет у `utility_pole` (наклон) и `cable_manhole` (форма люка, трещины, открытый).
